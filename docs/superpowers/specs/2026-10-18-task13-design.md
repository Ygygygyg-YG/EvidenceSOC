## 3. 模型与费用方案

## 5. 运行架构与数据契约

采用“控制器生成计划 → 单案隔离 worker 运行 → 原始输出封存 → 独立评分进程”的流程。控制器持有完整计划和数据准入引用；worker 只接收该案输入和无答案 run spec；评分侧才读取金标、适用掩码与人工复核资料。

核心接口提案：`async run_case(spec: WorkerRunSpec, agent_dir: Path) -> AdapterResult`。

- `ControllerRunSpec`：数据集、数据 manifest 与准入证据哈希、案例×组别计划、协议/实现/锁文件/模型/知识库版本、重跑策略、费用上限和审核配置。
- `WorkerRunSpec`：不泄漏标签的中性 run/case ID、组别、冻结配置哈希、模型参数、能力策略、种子规则和调用预算。不含金标路径、攻击/正常标签、场景说明或其他案例目录；case ID 映射由控制侧保留。
- `Diagnosis`：`verdict=attack|benign|unknown`、六类标签、`taxonomy_status`、来源、技术、阶段实例、事实声明及其 Evidence ID。允许 `attack + out_of_taxonomy`；不能用六类列表是否为空反推 verdict。
- `AdapterResult`：处置前 `diagnostic_snapshot`、独立的 `execution_status`、降级记录、可信 evidence registry、模型/工具逐次台账、资源用量、模拟验证结果和产物哈希。
- `AttemptRecord`：连续 attempt 编号、启动/完成时间、错误分类、是否获准重跑、配置/输入/输出哈希。状态与诊断分离；失败后已有诊断可审计，但主评分按冻结的执行失败规则处理。

所有组直接在真实分析调用中产出同一显式 Diagnosis，评测侧适配输出，不额外给某组增加一个隐藏的诊断 LLM。B3 复用原图并增加内部评测钩子，扩展 `agents/models.py` 和 `agents/state.py`，让三态诊断经原图状态/checkpoint保存并形成可信快照；不得复制一套看似六角色但行为不同的实验工作流。

评测路由按显式 verdict 决策：benign 正常结束诊断且不凭空生成处置方案；attack 即使 out_of_taxonomy 也可按可观察证据继续重构/响应，无法支持后续则转人工；unknown 最多按原规则回退取证一次，仍不足则转人工。公开响应契约保持兼容，必要内部状态及持久化影响在实施计划中逐项核对，不能让新 Diagnosis 只存在于 adapter 中而原图仍按空类型推断正常。

诊断快照在最后一次合法 analyze/reconstruct 后、首次 respond/approval/simulate 前封存。未知终止时保留 review 前最后一次分析，尚无合法诊断则记录 missing/failed；处置后证据和验证结论不得回写诊断指标。诊断完成与产品调查是否还在等待审批分别记录。

worker 复用 Task12 Docker 隔离方法，但另做真实模型进程验收：从固定提交导出必需源码，固定镜像 digest，不挂仓库根、`.git`、worktree 指针、docs、评分/标签、测试 fixture 或其他案例。只读挂载单案 agent、无答案配置与冻结知识资源；不隐式加载宿主 `.env`。案件使用独立数据库/索引或可证明的精确数据过滤，其他窗口也不可检索。

由实际发起模型请求并执行调查的同一 worker 做 nonce/PID/容器身份绑定探针，验证合法输入可读、控制侧金标 canary/Git/其他案不可读，控制器核对实际挂载和跨案拒绝。Task12 的 model-free MCP 报告不能替代该证据。输出独立回传，评分另起进程，不把评分结果反馈给运行中的模型。

| 内容 | 本设计的拟定规则 |

| 不可映射攻击 | 不进入六类分母；二分类、证据等继续按冻结适用性评分 |
| unknown / failed / missing | 有适用金标的计划行保留在主分母；未答不记正确，正类保留漏检。另报作答覆盖率、条件准确率和失败数量 |
| 失败后的已有诊断 | 以处置前诊断阶段是否成功确定诊断评分资格；诊断阶段失败的最后输出仅供误差分析，不作为成功回答。后续模拟失败不抹掉已成功诊断 |
| 二分类指标 | 报正类 Precision/Recall/F1、总体准确率、正常包 FPR 与未答率；另给二分类混淆计数。FPR 不能掩盖 unknown/失败，正常包正确判定率同步公开 |
| Evidence P@K | `K=5`；按最终诊断引用顺序去重，不足 5 条用空位计不相关；无适用相关性金标记 N/A。另给实际引用条数，不能只报较少引用的条件精度 |
| 引用有效率 | 引用存在、归属本案且与可信注册表匹配的引用数/全部引用数；无引用为 N/A，公开零引用报告比例，不算 100% |
| 阶段与顺序 | 仅用冻结的可区分实例和可比较先后关系；重复阶段不折叠成唯一阶段名；无可比较金标关系记 N/A |
| 用量缺失 | Token/费用缺失保持 null 和缺失原因，不填零；重试、失败、获准重跑与验证均计入成本 |

unknown 不能简单删除后再计算主 F1。评分器保留每类金标支持数、正确预测数和预测数；适用正类未答计漏检。正常案例的未答在总体准确率计未答对，单列正常未答率，避免靠全部弃答获得低 FPR。

Unsupported Claim Rate 与 Evidence P@K 的语义支持性由隔离评分资料和人工判断，引用存在性检查不能替代支持性。建议三日版预登记每个数据集 2 个攻击、2 个正常案例，覆盖八组，共64个审核槽位，来自8个底层案例×8组：按 seed42 在评分侧分层抽样并在正式输出前锁定名单，复核每份实际报告中全部事实声明和引用。失败、无报告或无声明均保留原因，不另换案例。抽样名单及类别留在评分侧，不给 worker；不能将64份报告当64个独立案例做显著性推断。

人工审阅时隐藏组别与模型信息，记录 supported/unsupported/无法判定、依据和审阅人；无法判定保留并报告上下界。发现争议需人工复核，Codex/LLM 不能担任最终裁判。UCR 及语义 P@K 明确标为该预登记样本的估计，公开逐数据集/组别的报告及声明覆盖数；未审报告不冒充已审。UCR≤5%仍保留为既定效果目标，本轮仅有抽样审核时将全量目标标为未判定；取得全量达标结论需增加预先约定的审核证据，不能用这64个槽位直接宣布全量通过。

AIT 沿用六类 Macro F1≥0.85、引用有效率≥95%、适用 ATT&CK F1≥0.80 等既定效果目标。DEDALE 拟新增包级攻击正类 F1≥0.85、正常包 FPR≤5% 作为效果目标，并强制同时公开作答覆盖率；这些是本设计提案，评审后在正式运行前冻结。N/A、适用覆盖不足或未完成的复核均不算效果达标。

## 7. 效果验证消融单独设计

704 项主要比较处置前诊断；A4 的差异在处置后验证，不预期通过改变诊断分数证明验证器有效。B3 的六角色链必须实际贯通，验证节点在此独立实验中验证；只跑到审批不能宣称完整六角色闭环已验收。

对 AIT 22 案和 DEDALE 66 案，预登记模拟成功、明确失败、无变化三种条件。704项中的B3/A4各自正常执行并封存诊断；额外的验证比较则对同案采用一个已封存的B3状态及合法、获批方案，克隆给“启用验证”和“禁用验证”两个分支，保证比较的是同一方案、动作、目标和观测。该复用只用于独立配对实验，不充当A4正式主项的实际执行，也不重跑或覆盖原诊断。这形成 `88×3=264` 个配对条件槽位、共528条分支记录，额外调用另计，不冒充704项的一部分。

每个条件及分支使用独立 worker/checkpoint、trace/验证run、验证账本与产物命名空间，条件ID为不含真值的opaque ID。现有run_id和validation_id存在按原案/方案稳定派生的路径，不能同案同状态顺序运行三次而复用首条件结果；实施时在隔离的数据库/状态副本中保留原方案及批准哈希，确保查询缓存、证据注册表和验证结果不跨条件复用或覆盖，并以三种不同观测的回归测试证明隔离。

只有具备合法响应方案及所需审批的案例才进入验证；全部264个配对槽位保留不可执行、拒绝、失败或完成状态，不事后用其他案例替换，不用两组不同的成功子集互相比。最低功能验收提案为AIT至少4案、DEDALE至少4案各跑完三种条件，即至少24个完整配对；该数量是非空功能覆盖门槛，不提供统计泛化保证。其余覆盖及正常案不需处置的原因照实公开；未达到该预登记门槛则验证消融未完成。审批使用现有方案/哈希校验，人工可批量审阅后逐案记录决定，不能伪造人工批准或绕过产品审批接口。禁用验证分支明确返回未验证，不能把未调用验证器记为处置成功或将其未作答记为零误报达标。

P3必须实现受控的处置后观测适配器、独立证据命名空间，以及 `evaluate_simulated_effect(action_type, before, after) -> success|failure|insufficient_evidence` 的冻结判定规则，并接入原validate节点。对既有三个模拟动作逐一使用类型化观测验证expected_effect；同目标证据仍存在不能直接判成功。明确失败证据判failure；无变化且不能证明效果时判insufficient_evidence。成功/失败/无变化的条件名、标签和真值只留在控制/评分侧，验证器实际读取观测值计算结果，不能由模拟器直接塞入validation_result；该节点维持确定性判定，不为实验虚增一个验证LLM。

分别报告配对条件上的验证误报成功率、明确失败识别率、无变化判断分布、可执行/审批/作答覆盖率及新增成本；静态日志和模拟证据均不能证明真实阻断。测试必须覆盖目标相同但处置后观测不同、条件名称不可见、证据缺失与未批准。若合法方案/审批覆盖不足，报告该限制，验证消融尚不足的部分保留为未完成。
